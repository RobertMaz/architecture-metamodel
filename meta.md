# Сводка: LikeC4-карта из Java/Kotlin ландшафта

## Принцип

Факты извлекаются детерминированно, LLM только осмысляет. Никогда не давать модели сырые исходники — только уже собранный JSON.

## Источники фактов (по приоритету)

| Источник                       | Что даёт                                  | Как                                                                        |
|--------------------------------|-------------------------------------------|----------------------------------------------------------------------------|
| **Spring Actuator**            | эндпоинты, граф бинов, конфиги, DNS-связи | `/mappings`, `/beans`, `/configprops`, `/env` через `kubectl port-forward` |
| **Tracing** (Jaeger/Tempo/DD)  | реальный граф вызовов                     | service map                                                                |
| **k8s манифесты**              | сервисы, ingress, env, брокеры, БД        | `kubectl get deploy,svc,ingress,cm -o yaml`                                |
| **jQAssistant**                | аннотации, зависимости, вызовы            | скан JAR-ов из Nexus → Neo4j → Cypher                                      |
| **OpenAPI / .proto**           | контракты                                 | springdoc                                                                  |
| **git log**                    | что живое, что мёртвое                    | churn за год                                                               |
| **Kafka UI / schema registry** | асинхронные связи                         | топики, продюсеры, консьюмеры                                              |
| **Люди**                       | намерение, домены, глоссарий              | разговоры                                                                  |

## Инструменты

**Брать:** Spring Actuator, jQAssistant (+Neo4j), `code-maat`, IntelliJ Ultimate Endpoints window, LikeC4 + `@likec4/mcp`.

**Не брать сейчас:** ArchUnit (это для CI, когда целевая архитектура известна), Structure101/Sonargraph (закупка), CodeScene (платно).

## Пайплайн

```
JAR из Nexus ──► jQAssistant ──┐
Actuator по dev ───────────────┼──► нормализованный JSON
k8s manifests ─────────────────┤    (сервис, эндпоинты, вызовы,
git log ───────────────────────┘     топики, БД, repo, команда)
                                            │
                                  LLM: JSON → .c4 DSL
                                  (имена, домены, description)
                                            │
                                  likec4 validate ◄─┐ цикл
                                            │───────┘
                                        LikeC4 MCP
```

Ничего локально запускать не нужно — всё снимается с dev и из гита.

## LikeC4: что делает карту рабочей

Не красота диаграмм, а **metadata + sourceLocation** — так модель становится индексом в код:

```
service ordersApi {
  #unverified
  metadata {
    repo 'git@...'; module 'services/orders'
    team 'checkout'; k8s 'orders-api'
    topics 'order-events,payment-done'
  }
}
```

Заглушки для неразобранного с `#todo` → `search-element` по тегу = твой бэклог онбординга. `#unverified` = что подтвердить с людьми.

MCP: `npx -y @likec4/mcp`, `LIKEC4_WORKSPACE=~/arch/model`. Инструменты: `search-element`, `read-element`, `read-deployment`,
`read-project-summary`.

## Kotlin: где байткод врёт

`inline`-функции исчезают в местах вызова, корутины превращаются в стейт-машины и рвут цепочки, extension-функции уезжают в `FileNameKt`. По
Kotlin-сервисам перепроверяй граф рантайм-источниками.

## Порядок первой недели

1. День 0: сообщение платформенной команде + доступы веером (git org read-all, kubectl, Grafana, Nexus, Kafka UI)
2. Клон всех репозиториев → инвентарь + churn
3. Снимок кластера → ingress = реальные точки входа
4. Actuator sweep по всем подам
5. jQAssistant по JAR-ам (ночь)
6. Нормализация в JSON
7. Генерация DSL + `likec4 validate`

Шаги 1–4 дают ~70% скелета за 2–3 дня.

## Не забыть

- **Журнал удивлений** с первого дня — свежий взгляд не восстанавливается
- **Глоссарий доменных терминов** — «заказ» в биллинге ≠ «заказ» в логистике
- **Постмортемы за год** — лучший источник про хрупкость системы
- Четыре вопроса каждому тимлиду: как ходит identity, кто source of truth по каждой сущности, где общие таблицы в БД, где монолит
- Задеплоить что-нибудь в прод на первой неделе
- Публиковать карту рано и криво, с пометкой «тыкайте где враньё»
- Топ-5 сервисов вглубь, 50 на уровне карты, для остальных знать кого спросить
