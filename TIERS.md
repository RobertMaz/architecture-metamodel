# Три круга: продукт, экосистема, внешнее

## Круг — это kind

```likec4
shop = system 'Интернет-магазин'         // наш продукт
auth = orgSystem 'Auth Platform'         // другая команда компании
psp  = externalSystem 'Payment Provider' // вне компании
```

Всё. Ни реестра, ни генератора, ни второго прохода экспорта.

**Почему kind, а не тег и не метаданные.** По нашему же критерию: kind заводится, когда различие меняет правила связывания. Круг их меняет — у трёх кругов разная разрешённая глубина и разные права доступа (см. ниже), и это проверяет линтер. Значит это kind.

Раньше круг выводился из `provider` через справочник команд. Это была ошибка: **круг меняется раз в несколько лет, а команды тасуют каждые полгода.** Выводить медленный факт из быстрого — значит без нужды ронять сборку на каждой реорганизации. Плюс лишний инструмент, лишний файл и лишний проход конвейера ради того, что и так видно в одной строке.

## Разная глубина — вот ради чего разделение

| kind | глубина | требуем | запрещаем |
|---|---|---|---|
| `system` | до эндпоинтов и схем | репозиторий, рунбук | — |
| `orgSystem` | только те контейнеры, которые **реально трогаем** | вызов через `#public` | описывать их внутренности «для полноты»; читать их хранилища |
| `externalSystem` | один узел, без внутренностей | `contract` (договор/SLA), `#stub` + подтверждение | описывать изнутри вообще |

```
ERROR psp                                внешняя система описана изнутри — это чёрный ящик
ERROR auth.theirCache                    чужой элемент, которым мы не пользуемся — не наша зона
ERROR shop.orders -[read]-> auth.authDb  прямой доступ в чужое хранилище
```

Третье — самое ценное: прямое чтение чужой базы обычно всплывает через год после того, как его сделали. Здесь оно не проходит сборку.

## Владение — в CODEOWNERS, а не в модели

`metadata.owner` убран. Он протухает молча: команду переименовали, а в модели она живёт ещё два года, и никто не замечает.

**CODEOWNERS протухнуть незаметно не может** — он назначает ревьюеров. Как только он врёт, PR уходит не тем людям, и это чинят в тот же день. Владение стоит держать там, где у него есть зубы.

```bash
$ npm run owners
shop   model/10-shop.c4   @acme/team-checkout
auth   model/10-shop.c4   @acme/team-checkout
```

`tools/owners.mjs` сопоставляет систему с файлом, где она объявлена, и резолвит владельца по правилам CODEOWNERS (побеждает последнее совпавшее — семантика git). Этим же владельцем `impact.mjs` подписывает список тех, кого надо предупредить.

Линтер следит за обеими сторонами:

```
ERROR shop.orders   metadata.owner дублирует CODEOWNERS — убрать, иначе разъедется
ERROR recommendations   нет записи в CODEOWNERS — непонятно, кто ревьюит и к кому идти
```

## Что осталось в metadata

Только то, что больше нигде не живёт и меняется само по себе:

```likec4
psp = externalSystem 'Payment Provider' {
  #public #stub
  link https://wiki.acme.io/integrations/psp 'confluence'
  metadata {
    contract 'MSA-2024-118, SLA 99.9'
    contact 'support@psp.example'
  }
}
```

Ссылки — через `link`, они кликабельны в интерфейсе. `metadata` — для номера договора, канала поддержки и подобного.

Правило: **если факт уже есть в системе, у которой есть зубы (CODEOWNERS, k8s, OpenAPI, справочник договоров) — в модели его не дублируем, а ссылаемся или выводим.** Дубликат всегда протухает, вопрос только в том, через сколько месяцев.

## Смена круга

| было → стало | что произошло | правка |
|---|---|---|
| `orgSystem` → `system` | систему передали нам | kind + строка в CODEOWNERS |
| `system` → `orgSystem` | отдали другой команде | kind, потом обрезать глубину до используемого |
| `externalSystem` → `orgSystem` | вендора заменили внутренним сервисом | kind + снять `#stub` |
| `orgSystem` → импорт | соседи завели свою модель | заменить блок на `import` |

Последний — самый желанный: наша реконструкция исчезает вместе со своим сроком годности и подтверждениями.
