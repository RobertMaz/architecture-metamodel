# Шпаргалка: как описать свой сервис

Одна страница. Если чего-то тут нет — значит, оно не нужно.

## Добавить сервис

Открой `model/<своя-система>.c4`, добавь ~10 строк:

```likec4
myService = service 'My Service' {
  technology 'Kotlin, Spring Boot'
  metadata {
    owner 'team-checkout'
  }
  link https://github.com/acme/my-service 'repo'
}

myService -[write]-> ordersDb
myService -[publish]-> orderCreated 'OrderCreatedV1'
```

`npm run check` — и в PR. Всё.

## Пять типов элементов

| kind | что это | правило |
|---|---|---|
| `client` | мобилка, SPA, терминал, CLI | только исходящие связи |
| `service` | принимает синхронные вызовы | — |
| `worker` | фоновая обработка, API нет | нельзя вызвать через `call` |
| `store` | БД, кэш, бакет | сам ничего не инициирует; **ровно один писатель** |
| `channel` | топик или очередь | входит только `publish`, выходит только `deliver` |

Postgres, Redis и S3 — это всё `store`, разница пишется в `technology`. Плодить kind'ы не надо.

## Пять типов связей

**Стрелка = направление данных. Всегда.**

```
orders ──publish──▶ order.created ──deliver──▶ billing
orders ──write────▶ orders-db
gw ─────call──────▶ orders
```

`call`, `publish`, `deliver`, `read`, `write` — больше ничего нет.

Никаких `A → B (via Kafka)`. Канал — это узел, иначе не видно, кто ещё его читает.

## Своё, соседнее, внешнее

```likec4
shop = system 'Интернет-магазин'         // наше
auth = orgSystem 'Auth Platform'         // другая команда компании
psp  = externalSystem 'Payment Provider' // вне компании
```

Глубина зависит от круга: своё — до эндпоинтов, соседей — только то, что реально вызываем, внешнее — одним узлом.

Владельца в модели не пишем: он в CODEOWNERS (`npm run owners`). Подробности: [TIERS.md](TIERS.md).

## Четыре тега

| тег | когда ставить |
|---|---|
| `#public` | доступен снаружи своей системы |
| `#pii` | лежат персональные данные |
| `#deprecated` | выключаем, идёт миграция |
| `#stub` | это наша **догадка** о чужой системе |
| `#inferred` | извлечено анализатором, человек не подтверждал (ставит генератор) |

`#stub` и `#inferred` — это **происхождение**, а не статус проверки. Тег не снимается после сверки: сверка только сбрасывает таймер.

```bash
npm run verify shop.orders.api --by=твой.логин --against=probe
# docs 90 дней | owner 180 | probe 365
```

Изменилась поверхность — подтверждение сгорает само. Подробности: [VERIFICATION.md](VERIFICATION.md).

## Эндпоинты

Руками не пишем. Слой генерируется из кода:

```bash
npm run gen      # tools/api-source/*.json -> model/gen/*.gen.c4
```

Если у твоего сервиса контракт уже сгенерирован, звонить в него надо в конкретный эндпоинт:

```likec4
gw -[call]-> orders.api.post_api_v1_orders     // так
gw -[call]-> orders                            // так линтер уронит
```

Кто сломается от изменения:

```bash
npm run impact shop.orders.api.post_api_v1_orders
```

Подробности — [CONTRACTS.md](CONTRACTS.md).

## Что не описываем

- **Классы и компоненты внутри сервиса** — меняются каждый спринт, читает только автор.
- **Схемы целиком** — в графе только сигнатура, полное тело в OpenAPI и в `tools/api-source/`.
- **Хосты, fqdn, реплики, зоны** — это знают k8s и terraform, и знают точнее.
- **Пути в очереди на уровне партиций** — избыточно.

Модель отвечает на три вопроса: что сломается при изменении, к кому идти, как проходит запрос. Всё, что не помогает ответить, — лишнее.

## Команды

```bash
npm run dev     # интерактивно, localhost:5173
npm run check   # синтаксис + инварианты, то же самое крутится в CI
npm run png     # картинки в build/images
```

## Если CI ругается

| сообщение | что делать |
|---|---|
| `нет записи в CODEOWNERS` | добавь свою систему в CODEOWNERS |
| `metadata.owner дублирует CODEOWNERS` | убери поле из модели |
| `shared database` | в одно хранилище пишут двое; либо это ошибка модели, либо реальная проблема |
| `у воркера нет публичного API` | либо это `service`, либо связь лишняя |
| `в канал ведёт только publish` | поменяй kind связи |
| `вход в чужую систему мимо #public` | либо цель публичная, либо так ходить нельзя |
| `DRIFT: живёт, но не описано` | сервис работает, а в модели его нет — допиши |
| `вызов должен вести в operation` | у сервиса есть контракт, звони в конкретный эндпоинт |
| `вызов эндпоинта, выключенного ...` | `sunset` прошёл, потребителя надо было мигрировать |
