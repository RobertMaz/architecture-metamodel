Строим **arch-analyzer** внутри репо architecture: конвейер улик (7 полок: source/config/bytecode/jqassistant/openapi/runtime/llm) → детерминированный реконсилятор → `tools/api-source/*.json` → расширенный генератор → `model/gen/`. Спека: `docs/superpowers/specs/2026-08-17-arch-analyzer-design.md`.

Ключевые решения пользователя:
- детерминизм — главный критерий; LLM (любой OpenAI-совместимый endpoint) только fallback/ревьюер/имена, confidence ≤ 0.7, кэш по хэшу входа; .c4 штампует генератор, не LLM;
- **CLI не будет вообще** — единственный интерфейс React 19 + Vite + Tailwind 4 + shadcn/ui (new-york, neutral, CSS-переменные) + TanStack Table/Query + react-router + radix + lucide; движок Kotlin + Ktor REST;
- всё в папке architecture (analyzer/, ui/, registry/, workspace/ в gitignore);
- итеративное дообогащение: evidence-файлы персистентны, дельта прогона видна как git diff;
- реестр: repos.yml + aliases.yml + unresolved.json, stub'ы в model/gen/unknown/, автосклейка по эндпоинтам/алиасам, append-only маппинг;
- системы (L0) — тоже данные: registry/systems.yml → gen/_systems.gen.c4, создание системы — шаг в UI при онбординге контейнера; владельцы только в CODEOWNERS; перенос контейнера между системами — id-aware rename-операция движка (не голый sed: подстроки; не запрет — пользователь настоял, что rename дёшев);
- приёмка на `~/IdeaProjects/spring-petclinic-microservices`;
- порядок: 1 ядро (source+config+реконсилятор+генератор) → 2 минимальный UI → 3 реестр → 4 bytecode+jqassistant → 5 llm → 6 runtime (Actuator+OTel javaagent).

**СТАТУС 2026-08-18: все 6 подпроектов реализованы и влиты в master.** Приёмка на полном petclinic (8 сервисов, включая genai/admin/config/discovery): 56 элементов, 32 связи, 0 ошибок check, прогоны идемпотентны, 67 Kotlin-тестов + 11 node-тестов зелёные. Особенности реализации: jqassistant — через адаптер-скрипт analyzer/jqassistant/extract.sh (формат `TYPE|attr=value|...|source|confidence`), Neo4j в сборку не тянется; LLM — любой OpenAI-совместимый endpoint (registry/llm.yml), кэш workspace/_llm-cache; runtime-факты персистентны в evidence после смерти апки; порт сервера 8081 в тестах (8080 на машине занят), UI на 5174. LLM-полка проверена живьём через OpenRouter (ключ в ~/.openrouter-key, модель qwen/qwen3.8-27b, registry/llm.yml закоммичен без ключа; сервер стартовать с LLM_API_KEY=$(cat ~/.openrouter-key)): enrich/ревью/гипотезы работают, кэш позволяет прогоны без ключа. Подпроект 7 (2026-08-18): очередь прогонов с одним воркером (queued→running→done|failed, sweep зависших при рестарте), PUT /api/containers/{id}/sources + карточка «Источники» (правка jar/runtimeUrl/traces после онбординга), резолюция `assign` — stub переезжает контейнером в явную систему (model/gen/observed/, api дообогащается из вызовов; сценарий sso/orgSystem юзера). Подпроект 8 (2026-08-18): раскладка по решению юзера — система анализатора целиком в `model/systems/<id>/<id>.c4` (контейнеры, сторы, каналы, связи И views: `<id>_containers` + `<id>_<name>_api` на контейнеры с контрактом, обёрнутые в `views '<Title>' {}` — папка системы в навигации LikeC4 (dsl/views/organize: общая папка у блока views, подпапки слэшем в title — «API / <контейнер>»)); `model/gen/` — ТОЛЬКО догадки (unknown/observed/_externals + легаси shop.orders). «Свои» контейнеры в gen не живут — юзер это явно потребовал. Overrides.c4 юзер заполнять НЕ будет: файлы систем правятся руками, git — арбитр (закоммиченное вытаскивается из diff после регенерации), незакоммиченные ручные правки генератор бэкапит в workspace/_backup/ перед перезаписью. Подпроект 9 «честный e2e» (2026-08-18): полный прогон живого petclinic всеми полками разом (6 полок на gateway/customers: source+config+bytecode+llm+runtime+traces), 49 связей. Новое: роуты Spring Cloud Gateway из yml (оба пути конфига + multi-doc `---`), полка traces ОТДЕЛЬНА от runtime (частично мёртвые источники не затирают чужой evidence), OTLP JSON-lines (logging-otlp пишет ResourceSpans без обёртки — grep нужен с -a!), peer.service > host (peer-service-mapping в javaagent, включая LAN-IP из eureka), числовые сегменты путей спанов → {_}. Живой стек: config 8888, discovery 8761, сервисы 9101-9104, gateway 9100; genai не стартует без OpenAI-ключа (vector store embeddings). Резолюции: config-server→petclinic.config, zipkin→external. Полка openapi реализована (последний пробел спеки закрыт): `openapi:` в repos.yml или автопоиск openapi.yml/api-docs.json, conf 0.95, приоритет между traces и source. E2e openapi на spring-petclinic-rest (система petrest, порт 9966, context /petclinic): якорная синхронизация путей спеки в реконсиляторе (суффиксы servers.url против эндпоинтов других полок — иначе дубли /owners vs /api/owners), actuator-маски `******` не адрес, онбординг пишет CODEOWNERS в /model/systems/<id>/. Api-группы по доменам (решение юзера: api = группа, operation = ручки; контейнер → api → operations): группа из tags спеки (приоритет) или имени контроллера (OwnerRestControllerV1→owner), операции без домена и fallback-рёбра — в базовом `api`, доменные — в `api_<slug>`; id операций получают нового родителя — рёбра согласованы генератором. UUID-имена in-memory БД (spring generate-unique-name) — не адрес (stableDbAddress). **ANALYZER.md** — человеческий ранбук запуска фулл-стека (сервер+UI+LikeC4, полки, снятие OTel-спанов, правила игры) — отправная точка для работы юзера на рабочей тачке. E2e-прогоны Playwright обязательны: находили реальные баги (CORS без PUT → 403 из браузера при работающем curl; неточечная инвалидация запросов).
